# GitHub 인기 AI 코딩 워크플로우 조사

> 이 문서는 2026-06-08에 GitHub stars 기준으로 확인한 AI 코딩 워크플로우/개발 방법론 조사 기록이다.
> 단순 IDE 확장이나 일반 코딩 agent보다, 개발 과정을 구조화하는 workflow, methodology, framework 성격의 프로젝트를 우선했다.

## 요약

GitHub stars 기준으로는 Superpowers, GitHub Spec Kit, GSD, OpenSpec, BMAD Method가 상위권이다. 이들은 모두 "AI에게 바로 코드를 맡기는 방식"보다 계획, spec, task, 검증, 리뷰를 구조화하는 방향을 가진다.

상위권 프로젝트의 공통 패턴:

```text
문제 정의
-> 요구사항 또는 spec 작성
-> 작업 분해
-> agent 구현
-> 테스트와 리뷰
-> 반복 수정
```

## 분류

### 가장 큰 traction

- Superpowers
- GitHub Spec Kit
- GSD
- OpenSpec
- BMAD Method

이 그룹은 stars 규모가 크고, AI 코딩을 개발 프로세스로 다루려는 명확한 방향이 있다.

### 프로젝트 관리에 가까운 도구

- Claude Task Master
- BMAD Method
- Spec Kitty

이 그룹은 PRD, task, subtask, story, kanban, sprint 같은 제품 개발 관리 단위와 잘 맞는다.

### Claude Code 강화 프레임워크

- Superpowers
- SuperClaude Framework
- bkit
- MoAI-ADK

이 그룹은 Claude Code 또는 비슷한 agentic coding harness에 명령, agent, skill, hook, MCP를 얹어 개발 흐름을 강화한다.

### spec-driven 중심

- GitHub Spec Kit
- OpenSpec
- Spec Kitty
- MoAI-ADK
- BMAD Method

이 그룹은 [[Spec-Driven Development]] 방향과 가장 잘 맞는다.

### 자동화와 검증 루프가 강한 도구

- bkit
- GSD
- Superpowers
- MoAI-ADK

이 그룹은 계획만 만드는 데 그치지 않고 agent 실행, 테스트, 리뷰, gap detection, self-repair 같은 반복 루프를 강조한다.

## 프로젝트별 메모

### Superpowers

Superpowers는 stars와 forks가 압도적으로 높다. README 기준으로 Claude Code, Codex CLI, Codex App, Gemini CLI, OpenCode, Cursor, GitHub Copilot CLI 등 여러 harness를 지원한다. 방법론은 brainstorm, worktree, planning, subagent execution, TDD, code review, branch finish에 가깝다.

판단:

- 개인 개발자와 agent-heavy workflow 사용자 사이에서 인기가 매우 높을 가능성이 있다.
- 단일 IDE보다 여러 agent 환경에 걸쳐 쓰려는 설계가 강점이다.
- stars 규모가 실제 기업 전사 도입을 뜻하지는 않는다.

### GitHub Spec Kit

GitHub Spec Kit은 GitHub 공식 spec-driven development toolkit이다. constitution, specify, plan, tasks, implement 같은 단계로 AI 구현 전에 요구사항과 설계를 구조화한다.

판단:

- 기업 도입 가능성은 매우 높다.
- [[Agentic DevOps]]와 결합하기 쉽다.
- GitHub 생태계의 공식 지원을 받는다는 점이 강하다.

### GSD

GSD는 context engineering과 spec-driven workflow를 결합한 프로젝트다. discuss, plan, execute, verify 흐름으로 빠르게 기능을 완성하는 방향을 가진다.

판단:

- 개발자 생산성 도구로 인기가 높다.
- 방법론 이름은 실용적이지만, 기업 표준으로 쓰인 공개 근거는 제한적이다.

### OpenSpec

OpenSpec은 변경 제안, spec, task를 먼저 만들고 구현하는 lightweight spec-driven framework다.

판단:

- [[Spec-Driven Development]]를 가볍게 시작하고 싶은 팀에 맞는다.
- BMAD보다 덜 무겁고, Spec Kit보다 독립적인 느낌이 강하다.

### BMAD Method

BMAD Method는 PRD, architecture, epic, story, sprint-status 같은 산출물을 중심으로 AI-driven agile을 운영한다.

판단:

- 큰 기능이나 제품 개발을 문서와 story 단위로 나누는 데 강하다.
- 기획, 설계, 구현 handoff가 필요한 팀에 적합하다.
- 대규모 기업 도입 근거는 아직 GitHub 인기도보다 약하다.

### Claude Task Master

Claude Task Master는 PRD를 task, subtask, dependency로 쪼개 agent가 실행 가능한 작업 목록으로 바꾸는 PM 계층이다.

판단:

- 전체 방법론이라기보다 AI agent 작업관리 레이어에 가깝다.
- BMAD, Spec Kit, OpenSpec 같은 spec-first 흐름과 결합하기 좋다.

### SuperClaude Framework

SuperClaude Framework는 Claude Code에 command, agent, persona, MCP를 추가하는 구조화 개발 플랫폼이다.

판단:

- Claude Code 중심 사용자에게 실용적이다.
- workflow 방법론보다는 Claude Code 운영 프레임워크에 가깝다.

### Spec Kitty

Spec Kitty는 spec, plan, tasks, agent loop, review, merge 흐름을 제공한다. git worktree, kanban, review가 강조된다.

판단:

- 작은 팀이 spec-first와 agent loop를 같이 도입하기 좋다.
- 인지도는 상위권보다 낮다.

### MoAI-ADK

MoAI-ADK는 SPEC-first agentic development kit이다. TDD, DDD, 품질 gate, 다중 agent 구성을 강조한다.

판단:

- 품질 gate와 구조적 설계를 중시하는 팀에 맞는다.
- 아직 대중성은 낮지만 방향은 기업형 workflow와 잘 맞는다.

### bkit

bkit은 Claude Code plugin 기반 PDCA workflow다.

```text
plan
-> design
-> do
-> analyze
-> iterate
-> report
```

판단:

- gap detector, QA/security agent, CTO-led agent team 같은 자동화 루프가 강하다.
- 현업 대중화 근거는 아직 약하지만, Claude Code 안에서 검증 중심 반복 개발을 실험하기 좋다.

## 종합 판단

GitHub 인기도만 보면 Superpowers가 압도적이다. 방법론 완성도와 조직 적용 가능성까지 보면 GitHub Spec Kit, BMAD Method, OpenSpec, GSD, Superpowers를 우선 검토할 만하다.

현업 적용 관점에서는 다음 조합이 현실적이다.

| 상황 | 추천 후보 |
|---|---|
| GitHub Enterprise 중심 조직 | GitHub Spec Kit + [[Agentic DevOps]] |
| spec-first를 가볍게 시작할 팀 | OpenSpec 또는 Spec Kitty |
| 제품 기획과 story 기반 개발 | BMAD Method |
| Claude Code 중심 개인/소규모 팀 | Superpowers, SuperClaude, bkit |
| PRD를 agent task로 바꾸고 싶은 팀 | Claude Task Master |
| 품질 gate와 반복 검증을 중시하는 팀 | bkit, MoAI-ADK, GSD |
